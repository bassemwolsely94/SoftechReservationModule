## 7. Rules and traps the new session must know

All of `CLAUDE.md` applies. In addition, from experience on this project:

- **Stop and ask** before: schema changes affecting SOFTECH sync, any discount/pricing calculation change, anything touching payment/checkout completion, anything that could double-post to SOFTECH, and the first production tax send.
- **SOFTECH writes**: only through the guarded plan pattern (dry-run default, flag in `config/writers.py`, idempotency guard, audit, manifest entry). Never write branch 100 rate rows. Never blind-pick a POS test item (`itemarchive='0'` required; item 100000 archived). Insurance reprice only via `softech_guard` + `SoftechWritePlan` (incident: run 282).
- **SOFTECH reads**: only through `config/sybase.py`. docnumbers collide per (branch, doctype) — never query a bare docnumber; always include doccode. jConnect: never `getColumnTypeName`; use `SET ROWCOUNT`, not `TOP`.
- **Tests**: never run test suites in parallel or two sweeps at once (Postgres on the office PC ran out of memory twice on 2026-11-12). Use a unique `TEST_DB_NAME` per run; copy a kept DB (`CREATE DATABASE x TEMPLATE y`) + `--keepdb --noinput`. Security sweeps serially. Check RAM and stray `rg.exe` before long runs. Let CI run the full suite.
- **Merging**: the repo has **no required checks**, so `gh pr merge --auto` merges at once. Wait for all checks to be green, then merge by hand. Never push straight to `main`. `git fetch` first — other sessions merge too. Never force-push.
- **Migration numbers collide** between parallel branches (it happened in users, notifications, audit, finance). Re-check numbers against `main` right before every push; renumber, don't duplicate.
- **After every tested batch**: merge to `main`, push, fast-forward local `main` (and the laptop folder) — owner preference.
- **Every new screen/tab/status** needs in-app help in Arabic + English with a bumped `updated` date.
- **UI conventions**: never show a bare branch code (use branch labels, also in Excel); «سيرفر» not «خادم»; progress bar for syncs/long jobs; every sync-fed screen gets a forced-refresh button (DataFreshnessBar domains); every table sortable; review grids get the keyboard hook (↑↓ Space Enter M Ctrl+A); wildcard search via `apps/catalog/wildcard.py`; RTL arrows via `utils/flowArrow`.
- **Liveness of a branch = `Branch.kind`** (never `is_active`). Store 110 is a closed branch and is excluded everywhere. People groupings are crews «طاقم», never a fake branch.
- **New background threads**: `core.threads.start_thread`, never bare `Thread`. New scheduler jobs: add to `SCHEDULER_JOB_GUARDS`.
- **Privacy**: phones masked via `apps/customers/access.py`; errors via `core/errors.public_error`; exports via `core/export_safety.py`.
