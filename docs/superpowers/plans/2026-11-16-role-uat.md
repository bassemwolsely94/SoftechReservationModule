# Role-by-role UAT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local UAT copy of production data plus a Playwright suite that proves, per role and per user shape, screen visibility, button visibility, phone/branch exposure and daily workflows — and a findings report.

**Architecture:** Phase 0 (this session) builds the shared foundation: `config/settings_uat.py`, a DB refresh script, `seed_uat_users`, `export_uat_expectations`, and a Playwright UAT harness (`frontend/playwright.uat.config.js`, `frontend/uat/lib/*`). Phase 1 runs five workstreams in parallel sessions, each in its own folder under `frontend/uat/`. Phase 2 (this session) does the hands-on pass and writes the report.

**Tech Stack:** Django 4.2 management commands, Django test runner, Playwright 1.64 (Chromium), PowerShell, PostgreSQL 16 `pg_dump`/`pg_restore`, Locust.

**Spec:** `docs/superpowers/specs/2026-11-16-role-uat-design.md`

## Global Constraints

- Never use the repo `.env`, the office runtime (port 8000), or database `elrezeiky_db` for anything but the read side of `pg_dump`.
- UAT database name must match `elrezeiky_uat*`; `settings_uat` raises otherwise.
- UAT ports: backend `127.0.0.1:8200` (one shared server, started from the `role-uat` worktree); Vite `5200` here, each parallel session its own `UAT_WEB_PORT` (5201–5206).
- `WRITER_INSTANCE=False`, `SOFTECH_READ_ONLY=True`, no SOFTECH host, every writer/send flag off, messaging/AMI/AI/ETA keys blank, `SCHEDULER_AUTOSTART=False`, `RBAC_ENFORCEMENT='enforce'`.
- Never run `seed_permissions` against the UAT database.
- Credentials and real reference data (phones) only in git-ignored files: `frontend/uat/.uat-users.json`, `frontend/uat/.uat-expected.json`. Never printed, never in reports — reports cite record ids and the last 3 digits only.
- Heavy runs (DB refresh, full sweep of any workstream, load) take the lock `scripts/uat/heavy.ps1` (lock file `%TEMP%\elrezeiky-uat-heavy.lock`); a single spec file while developing is not heavy.
- POS push and pricing/discount approval may be completed end to end **on the copy only**, after asserting `GET /api/sync/writer-status/`-equivalent (see Task 1) says reader and the push result has `dry_run: true`.
- In-app help: no new screens are added, so no `apps/help` change; if a workstream adds one, CLAUDE.md step 5b applies.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Login throttle (10/min/IP) and account lockout** — logging in 30+ UAT users in a row must not lock anyone out; `settings_uat` raises the throttle and the login setup paces itself (Task 1 test, Task 5 setup).
2. **Real users with TOTP / required-2FA roles (admin, purchasing, supervisor)** — `seed_uat_users` must turn 2FA off for every UAT and sampled real user on the copy, else login setup hangs on the code screen (Task 3 test).
3. **A real user who is inactive, has no StaffProfile, or no branch** — `--real` must refuse with a clear message, not create a half user (Task 3 test).
4. **Copy restored from an older schema** — refresh must run `migrate` and fail loudly on a migration error rather than leave a half-migrated DB (Task 2 verify step).
5. **Huge lists on real volume (1.7M purchase history, 879k notifications)** — specs must wait for a settled page (no spinner) with a 60 s cap and record "slow" instead of failing as "missing" (Task 5 `gotoSettled`).

## Phase 1 — parallel workstreams (one session each, own worktree branched from `claude/role-uat` after Phase 0)

Each session: read the spec + this plan; touch only its own folder (plus the files listed); develop single specs against the shared 8200 backend with its own `UAT_WEB_PORT`; run its full suite only through `scripts/uat/heavy.ps1`; commit on its own branch; report the findings count by kind/severity.

### Task 6 (W2): Visibility sweep — `frontend/uat/visibility/`
- Routes = every `<Route path>` in `src/App.jsx` (parse, skip `:param` routes unless `navApi`/reference gives an id) ∪ `navGroups` items ∪ mobile `/m/*` list in `App.jsx`.
- Per user × route: menu shown? (`navItemVisible` vs expected `can(key, module,'view')`), `gotoSettled` result, console/API errors, ms.
- Rules: hidden+refused = pass; visible+ok = pass; `KNOWN_GAPS` pair rendering = pass; shown but refused → P2 `screen`; hidden but renders and not in KNOWN_GAPS → P1 `screen`; `crash`/5xx → P1 `crash`; `blank` → P2; ms > 5000 → `slow`.
- Output: `test-results-uat/visibility-matrix.json` (user × route → status, ms).

### Task 7 (W3): Buttons — `frontend/uat/buttons/` + `src/components/CanDo.jsx`, `src/hooks/usePermission.js` call sites
- `CanDo` wraps allowed children in `<span data-perm={`${module}:${action}`} style={{display:'contents'}}>`; vitest in `CanDo.test.jsx` proves attribute present and layout-neutral (no extra box). Same attribute added at the 8 `usePermission(` call sites' buttons.
- Spec: per user × screen that rendered `ok` in W2's matrix (or its own pass), every `[data-perm]` must be `can()`=true (else P1 `button`); for each screen's known primary actions in a small table `buttons/primaryActions.js`, allowed but missing → P3.
- Catalogue `docs/uat/role-checks-catalogue.md`: every `user.role`/`user?.role` check in `src/` with file:line, roles allowed, inferred module:action ("inferred — needs confirmation"), and a looser/stricter-than-table verdict (looser = P1, stricter = P3) also emitted as findings.

### Task 8 (W4): Phones and branches on screen — `frontend/uat/exposure/`
- Rules table `exposure/rules.js`: per domain (customers, customer360, reservations, demand, followups, transfers, pos, delivery, callcenter, insurance, referral, loyalty, pic-analytics, exports, search/Ctrl+K, mobile) → `absent | masked | full` per user shape, derived from design §7.1 (B-1/B-2/B-3, all-branch roles, reasoned lines in `apps/tests/security/baselines/branch_canary_leaks.txt` / `phone_canary_leaks.txt`). Unknown → `decision`.
- Checks: page text + intercepted JSON responses scanned for each reference phone's full digits (normalise spaces/dashes/+20) and for branch-A reference ids when the rule says absent; Excel exports downloaded and scanned (use `xlsx` already in frontend deps if present, else read via the existing backend export endpoint JSON). Full phone where masked → P0 `phone`; branch-A record where absent → P0 `branch`; over-masking where `full` → P3.

### Task 9 (W5a): Operational workflows — `frontend/uat/workflows/ops/`
Reservations (create → fulfil), demand + follow-up, transfers (request → approve → receive), shortage list, stock count + daily count, delivery dispatch, call-center case. Each: run as roles that do it (from `can()`), and a refusal check for one role that must not. Notes prefixed `UAT-`. Failure → P1 `workflow`.

### Task 10 (W5b): Money and approval workflows — `frontend/uat/workflows/money/`
POS order → ready → push (assert reader + `dry_run: true` first), pricing/discount request → approve (copy only, owner-approved), operational approvals, insurance claim review, supply/ISR review, GL manual entry, vouchers OTP flow (OTP read from the API test hook only if one exists — else stop at "OTP sent" and mark `decision`), HR leave request. Same rules.

### Task 11 (W7): Light load — `deploy/loadtest/locustfile.py`, `scripts/uat/run_light_load.ps1`
Extend the locustfile with a `UAT_USERS_JSON` role mix (pharmacist/salesperson heavy, call_center, supervisor); run 5 → 10 users × 10 min headless via `heavy.ps1`; write `docs/uat/light-load.md` (p50/p95 per endpoint, failures, slowest 15).
